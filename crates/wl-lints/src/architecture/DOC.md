# architecture

Enforces workspace layering: which crates may import which canonical paths.
Judged on the compiler's resolved reference graph, so every re-export chain
and macro-generated reference is seen.

A semantic lint, enabled whenever at least one rule is present. It needs a
compiling workspace and the extraction tier; `--fast-only` skips it.

## What it checks

Each rule names a set of importing crates (`from`) and forbidden import
targets (`deny`), with an optional per-target `exceptions` escape hatch.
Three reference forms are inspected:

- `use` bindings,
- glob imports (`use mod::*`),
- fully-qualified call sites with no `use`
  (`other_crate::infra::Thing::new()`).

A fully-qualified reference is matched against its canonical path *and every
prefix* — so `Thing::new()` matches a `Thing` deny — and an `exceptions`
entry on any prefix (e.g. `infra::Id`) exempts the whole reference. A given
target is reported at most once per rule per module: a violation already
surfaced through its `use` binding is not repeated by the call-site pass,
and N call sites collapse to one diagnostic.

Canonical paths are the compiler's resolved answer, so every re-export chain
(`pub use` *and* `pub(crate) use`) resolves to the definition, and
references generated by macro expansions are judged too, anchored at the
invocation line. Only each crate's production code is inspected — tests,
examples, and benches legitimately reach across layers.

## Configuration

One `[[architecture.rules]]` table per rule. Presence of any rule enables
the lint.

```toml
[[architecture.rules]]
name = "domain stays pure"          # optional, shown in the diagnostic
from = ["domain-*"]                 # importing-crate name globs (required)
deny = ["*::infra::*", "sqlx::*"]   # forbidden canonical-path globs (required)
exceptions = ["infra::Id"]          # canonical paths allowed despite deny
severity = "deny"                   # "warn" (default) or "deny"
reason = "domain must not depend on infrastructure"  # note: line
suggest = "move the shared type into a `core` crate" # help: line
```

- `from` / `deny` — required; the importing crates and the forbidden
  targets.
- `name` / `reason` / `suggest` — optional prose surfaced in the diagnostic.
- `exceptions` — canonical paths allowed despite matching `deny`.
- `severity` — this rule's own level; overrides the `[lints]` level for its
  findings.

Patterns use `::` as the segment separator; `*` matches one segment, `**`
matches zero or more.

`architecture` is TOML-only (its rules are too structured for flags), so it
has no `check` subcommand — but `workspace-lint explain architecture` works.

## Silencing

Set a rule's `severity = "warn"`, remove the rule, or add an `exceptions`
entry for a legitimate crossing. For a one-off, write an `expect` directive
at the importing site.
